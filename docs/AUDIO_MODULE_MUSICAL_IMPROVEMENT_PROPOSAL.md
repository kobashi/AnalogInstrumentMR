# 音響モジュール 音楽表現改善提案

AnalogInstrumentMR のモジュラー音響システムを、音楽的に豊かな表現ができるようにするための提案。

- 作成: Claude Opus 5.5（2026-09-26）
- 状態: **提案**。コードは変更していない。実装は Codex が担当する
- 根拠: `Assets/MatsuMotoMeterAR/Runtime/Audio/` の実装を読んだもの（ブランチ `codex/audio-module-visuals`、`d419d44` の作業ツリー）
- 同内容の Claude Docs 版あり。このファイルは単独で読めるように書いてある

---

## 要約

**一番の問題は音程だ。現状のシーケンサは平均律の音をほとんど出せない。** ステップ値の刻み（0.05）と音高の対応（±1 → ±2 オクターブ）の組み合わせで、**1 刻みが 1.2 半音（120 セント）**になっている。平均律に乗るのはユニゾン・三全音・オクターブだけで、**完全 5 度も長 3 度も弾けない**。初期メロディは 16 音中 11 音が 20〜40 セント外れている。

これを直すだけで「鳴る装置」が「弾ける楽器」になる。変更は定数 1 つと、保存済みパッチの移行。

その後に効くのは、費用の小さい順にこの 4 つ。

1. **音程** — 半音グリッド、スケール量子化モジュール、音名表示
2. **時間** — 休符、アクセント、スウィング、テンポ同期
3. **音色と質感** — 帯域制限波形、フィルタモード、指数エンベロープ、ソフトクリップ
4. **計器を楽器に** — メーターやトレンドのデータを、量子化とグライドで旋律に変える。**このプロジェクトにしかない強み**

## 現状の制約

一般論ではなく、すべてコード上の根拠がある。

### 音程

**1 刻み = 120 セント。** `ModularAudioParameterPolicy.SequencerStepIncrement = 0.05`、Oscillator の `pitch.in` は `control × 2` オクターブ。よって 0.05 × 24 半音 = 1.2 半音。

| 刻み数 | 音程 | 平均律からのずれ（セント） |
|---:|---|---:|
| 0 | ユニゾン | 0 |
| 4 | 4.8 半音（長 3 度の近辺） | −20 |
| 5 | 6.0 半音（三全音） | **0** |
| 6 | 7.2 半音（完全 5 度の近辺） | +20 |
| 10 | 12.0 半音（オクターブ） | **0** |

40 セントは四分の一音（50 セント）に近く、誰にでも聞き分けられる。

初期メロディ（`DefaultSequencerSteps`）を半音換算した結果:

```
-0.50 -> -12.0 st  C  +0      -0.60 -> -14.4 st  A# -40
+0.00 ->  +0.0 st  C  +0      -0.05 ->  -1.2 st  B  -20
+0.45 -> +10.8 st  B  -20     +0.55 -> +13.2 st  C# +20
-0.15 ->  -3.6 st  G# +40     +0.10 ->  +2.4 st  D  +40
+0.65 -> +15.6 st  E  -40     +0.75 -> +18.0 st  F# +0
+0.20 ->  +4.8 st  F  -20     +0.30 ->  +7.2 st  G  +20
-0.35 ->  -8.4 st  E  -40     -0.25 ->  -6.0 st  F# +0
+0.35 ->  +8.4 st  G# +40     +0.50 -> +12.0 st  C  +0
```

**外れているのは 16 音中 11 音。**

**量子化の手段がない。** LFO や計器の連続値を `pitch.in` へ入れると音程のない滑りになる。スケールもルートもない。基準周波数は Hz の生値（初期 220）。

### 時間

- **ゲート長は全ステップ共通**。ステップごとの休符、タイ、アクセントがない。**休符がないとリズムが作れない**
- 進行は前進のみ。長さは 8 か 16 のみ
- スウィングがない
- LFO（0.01〜40 Hz）と Delay（0.02〜0.75 s）は**テンポに同期しない**

### 音色

- **波形が帯域制限されていない**。Saw は `phase × 2 − 1` のままで、高い音域でエイリアス（音程と無関係な折り返し音）が出る。Square も同じ
- **フィルタはローパスのみ**。ただし実装は状態変数型（TPT SVF）で、**バンドパスは内部で既に計算している**。出していないだけ
- **エンベロープは全区間が直線**。自然な減衰は指数曲線で、直線の Release は最後でぶつ切れて聞こえる

### 変調

- **Control は 1 ブロックに 1 回**（ブロック先頭の値だけ。最大 1024 サンプル = 48 kHz で約 21 ms）。ビブラートやフィルタスイープが段になる。VCA と Filter は 5 ms の平滑化でザッパーノイズを抑えているが、速い形は作れない
- **変調の深さを決める手段がない**。複数ケーブルは足されるだけで、ケーブルごとの量も反転もない。エンベロープは 0〜1 の単極のみ

### ミックス

- **Mixer と AudioOutput は ±0.85 で硬いクリップ**。音が重なるとデジタル的に割れる
- **Mixer は入力 1 つに全部足すだけ**。チャンネルごとの音量がない
- **Delay は整数サンプル読み出し**（補間なし）。時間を動かすとクリックが出る。帰還路にフィルタがなく、繰り返しが暗くならない

### 既にある強み

- **各 AudioOutput は部屋の中の点音源**（`spatialBlend = 1`）。モノラルだが空間化されているので、**出力を置く場所そのものが定位になる**。パンを足す必要はない
- **計器が信号源になる**。Meter / Trend / Panel は value、slope、spread、energy、balance、phase、detail の Control と trigger を出す
- フィルタは質の良い実装（SVF、係数平滑化あり）、ゲートとトリガはサンプル単位で正確

## 提案

費用は **小 / 中 / 大** の 3 段階。

### A. 音程

**A1. ステップの刻みを半音にする**（費用: 小、効果: 最大）

`SequencerStepIncrement` を 0.05 から **1/24**（≈ 0.041667）へ。±1 = ±24 半音のままなので、**1 刻みが正確に 1 半音**になる。変更は定数 1 つと初期メロディの差し替え。

**注意**：保存済みパッチのステップ値は 0.05 刻みで入っているので、新しいグリッドで再量子化すると音が動く。**保存形式に版を持たせて移行する**か、「最も近い半音に寄せる」規則で一度だけ変換する必要がある。

**A2. 量子化モジュール（Quantizer）を足す**（費用: 小〜中、効果: 大）

`control.in` → `control.out`。入力を指定スケールの最も近い音へ寄せる。設定は **スケール**（半音 / 長調 / 短調 / ペンタトニック長・短 / ドリアン）と **ルート**（C〜B）。音が変わった瞬間に `trigger.out` も出す。

これがあると **LFO、ノイズ、計器の値が、全部旋律になる**。ペンタトニックにしておけば何を入れても濁らない。

**A3. 音名で表示する**（費用: 小）

ステップ値を `+0.45` ではなく `B4` のように表示する。基準周波数も Hz ではなく**音名＋オクターブ**で選べるようにする。

### B. 時間

**B1. ステップごとの休符**（費用: 小、効果: 大）

各ステップに ON / OFF を持たせ、OFF のステップでは `gate.out` と `trigger.out` を出さない。**音数の減ることがリズムを生む**。現状では 16 ステップが全部均等に鳴るので、どう弄っても「ピコピコ」にしかならない。

**B2. アクセントとタイ**（費用: 中）

- **アクセント**：ステップごとの強調。別の Control 出力（`accent.out`）として出し、VCA やフィルタへ入れる
- **タイ**：次のステップまでゲートを閉じない。レガートと長い音が作れる

**B3. スウィング**（費用: 小）

偶数ステップを少し遅らせる（0〜30 %）。内部テンポの位相計算に係数を掛けるだけ。

**B4. テンポ同期**（費用: 中）

LFO と Delay に `clock.in` を足し、周期を **1/4、1/8、付点 1/8** のような拍の分数で指定できるようにする。

**B5. 進行方向と確率**（費用: 中、優先度は低）

逆行 / 往復 / ランダム、ステップごとの発音確率。

### C. 音色と質感

**C1. 帯域制限された波形**（費用: 小、効果: 中）

Saw と Square に **PolyBLEP**（不連続点の前後 1 サンプルを多項式で滑らかにする手法）を入れる。計算は数行で、Quest の CPU 予算にほぼ影響しない。

**C2. フィルタのモード**（費用: 小、効果: 中）

ローパスに加えて**ハイパスとバンドパス**。SVF は内部で既にバンドパスを計算しており、ハイパスは「入力 − ロー − k×バンド」で得られるので、**出力するものを選ぶだけ**。

**C3. 指数曲線のエンベロープ**（費用: 小、効果: 中）

Decay と Release を指数減衰にする。曲線を切り替える設定にして、現状の音も残せる。

**C4. ソフトクリップ**（費用: 小、効果: 中）

Mixer と AudioOutput の硬いクリップを `tanh` などの緩やかな飽和にする。音が重なっても「割れる」のではなく「太る」。

**C5. オシレータの厚み**（費用: 中、優先度は低）

PWM、微小デチューンした 2 層（ユニゾン）、サブオクターブ。計算量も増える。

### D. 変調

**D1. Control をブロック内で補間する**（費用: 小〜中、効果: 大）

現状はブロック先頭の 1 値。これを「前ブロックの値から今の値へ線形に動かす」に変える。設計を変えずに**ビブラートやスイープの段が消える**。

**D2. ケーブルごとの量（アッテヌバーター）**（費用: 中、効果: 大）

各 Control ケーブルに −1〜+1 の量を持たせる。**「少しだけ」と「逆向きに」ができるようになる**。ケーブルの保存形式に数値が一つ増えるので、A1 と同じく保存データの版管理が要る。

**D3. グライド（Slew）モジュール**（費用: 小、効果: 中）

Control の急な変化を滑らかにする。シーケンサとオシレータの間に入れればポルタメント。

### E. ミックスと空間

**E1. Mixer にチャンネルごとの音量**（費用: 中、優先度は低）

入力を `audio.in.1〜4` に分ける。E3 があれば当面必要ない。

**E2. Delay の質**（費用: 小〜中）

- 読み出しを**線形補間**にして、時間を動かしてもクリックしないように
- 帰還路に**ローパス**。繰り返すたびに暗くなる
- 最大時間を 0.75 s から延ばす（120 BPM の 2 分音符 = 1 s が入らない）

**E3. 空間配置を楽器の一部にする**（費用: 小）

パンを足さず、出力を複数置くことを前提にする。ベースを左の壁、リードを右側、ディレイを背後に置けば、それがミックスになる。必要なのはドキュメントとプリセットだけ。

### F. 計器を楽器に

**F1. 計器 → 量子化 → オシレータ を標準プリセットに**

`Meter.value.out → Quantizer（ペンタトニック）→ Slew → Oscillator.pitch.in`。計器の値がそのまま濁らない旋律になる。A2 と D3 があれば追加実装はプリセットだけ。

**F2. 計器の閾値をリズムに**

計器の `trigger.out` を `Sequencer.trigger.in`（StepTrigger モード）へ入れれば、**計器が閾値を越えるたびに旋律が 1 歩進む**。**既存機能だけで組める**ので、例として文書化する。

**F3. レバーとスロットルを演奏用に**

Lever / Throttle / Rotary は `ControlSource` として Control を出せる。D2 の量調整が入れば、MR の中で体を使って演奏できる。

## 優先順位と段階

各段階の終わりで実機で音を確かめてから次へ進む。

### 第 1 段階：弾けるようにする

| 項目 | 費用 | 効果 |
|---|---|---|
| A1 半音グリッド＋保存データ移行 | 小 | 最大 |
| A3 音名表示 | 小 | 大 |
| B1 ステップごとの休符 | 小 | 大 |
| A2 量子化モジュール | 小〜中 | 大 |

### 第 2 段階：音を良くする

| 項目 | 費用 | 効果 |
|---|---|---|
| C1 帯域制限波形（PolyBLEP） | 小 | 中 |
| C4 ソフトクリップ | 小 | 中 |
| C3 指数エンベロープ | 小 | 中 |
| C2 フィルタモード | 小 | 中 |
| D1 Control のブロック内補間 | 小〜中 | 大 |

どれも局所的な変更で、既存パッチの振る舞いは変わらない（C3 と C2 は設定で切り替え、初期値は現状）。

### 第 3 段階：表現の幅を広げる

| 項目 | 費用 | 効果 |
|---|---|---|
| D2 ケーブルごとの量 | 中 | 大 |

F1〜F3 のプリセットと、E3 の空間配置の手引き。実装はほぼ不要で、A2、D2、D3 が前提。

## 検証の仕方

### 音楽的な正しさを自動で測る

既存の EditMode テストに足せる形で。

| 測るもの | 方法 | 合格条件 |
|---|---|---|
| 音程（A1、A2） | 各ステップ値をレンダリングして零交差から周波数を求める | 平均律から **±1 セント以内** |
| エイリアス（C1） | 高い Saw を FFT、倍音以外の成分を測る | 現状比で大きく減ること |
| 変調の段（D1） | 1 Hz LFO → VCA をレンダリング、隣接サンプル間の最大差 | ブロック境界に段がないこと |
| クリップ（C4） | 過入力時の波形 | 角のない飽和 |
| 休符（B1） | OFF ステップでの gate / trigger | どちらも 0 |

**音程のテストは最初に書く。** 現状のコードに対して流せば、この文書が指摘した「11/16 音が外れている」を**落とす**はずで、それが検査が機能していることの証明になる。修正後に通れば、その合格に意味がある。

### 耳で確かめる

各段階の終わりで、Quest 実機に同じデモパッチを鳴らし、修正前後を録音して比べる。数字が合格しても、最後は耳で判断する。

### 性能

`InstrumentAudioVoiceBudget` の声部数予算がある。C5 と、将来の完全なサンプル単位 Control は負荷を増やすので、入れる前に 1 声部あたりの処理時間を測る。

### やらないこと

- **ポリフォニーと鍵盤入力**。規模が変わる。複数の単音ボイスを並べれば和音は作れる
- **ステレオのパン**。E3 のとおり不要
- **5 つの信号ドメインの見直し**。枠組みは正しく機能している
- **完全なサンプル単位 Control への再設計**。D1 の補間でほぼ解消する
