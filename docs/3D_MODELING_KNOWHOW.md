## この知見の出どころ

MR用アナログ計器アプリで、既存テーマを一切変更せず、独立した第5テーマ「Superfine」を新規制作した工程から得たもの。音響10機種と非音響14機種の計24機種を、Blender 5.2 のヘッドレススクリプトだけで作図し、決定的な FBX として納品した。作業は Codex（Unity側）との二者分担で、発注と受領はすべて番号付きの共有文書1本に記録した。

規模の目安として、非音響14機種は 1,048〜3,976 triangles、参照した既存の本番アセットは 190〜6,880 triangles。つまり**ポリゴン数を増やさずに説得力を上げる**ことが主題だった。

重要なのは、この工程で出た欠陥のほとんどが「見て気づいたもの」ではなく「検査が捕まえたもの」だった点。そして最大の欠陥は、**当時のすべての検査を通過して実機まで到達した**。以下はその反省が中心になる。

## 設計ミスを防ぐ：検査の設計

### 1. 一つの面には複数の座標フレームがある。検査したのはどれか

この工程で最も高くついた欠陥。表示パネルの表示面が、Quest実機で何も描画されなかった。

当時の検査はすべて通っていた——root-local で法線 +Z、triangle winding 正、determinant 正、UV0 あり、手前に遮蔽物なし。だが実際の原因は **mesh 自身の local bounds** だった。作図時にパネル面を Blender の XZ 平面に置き、FBX export の軸変換が root node に乗るため、mesh data は無変換で書き出される。Unity から見た mesh-local bounds は `(1.384, 0.000, 0.664)` ——**Y extent が 0**。ランタイムは表示 mesh の local X/Y から図形寸法を取っていたので、height 0 → scale `(0,0,0)` → 不可視。

一般則にすると：**ある座標系で正しいことは、別の座標系について何も保証しない。** 消費側（ランタイム、シェーダ、物理、UI）がどのフレームの数値を読むかを列挙し、そのすべてで表明を書く。mesh-local / object / node-local / root-local / world は別物として扱う。

修正は、立ち上げを mesh から object transform へ移すこと。頂点 `(x, y0, z)` → `(x, z, 0)`、object に `Rx(+90°)` と offset。world 位置は完全に同一のまま、mesh-local が `(1.384, 0.664, 0)` になり、ランタイム scale は `(0,0,0)` から `0.543` へ回復した。

### 2. 検査は「区別できる」ことを先に証明する

検査が通ったことに意味があるのは、その検査が不良を落とせると分かっているときだけ。実例が3つある。

- **測定器を既知の正解で較正する。** 修正に入る前に、自作の FBX 生座標リーダーが、Unity側が報告した既知の実測値 `(1.384, 0.000, 0.664)` を再現することを確認した。これが合わなければ以降の数字はすべて無意味だった。**新しい測定手段は、答えの分かっている対象で当ててから使う。**
- **通らない理由が的外れな検査は害。** 発光体の検査に `semantic_role` というカスタムプロパティを使っていたが、これは FBX export で消える。実体は正しいのに FAIL が出続けた。「オブジェクトが独立して存在し独自マテリアルを持つか」という、export を越えて生き残る事実で書き直した。
- **反証が崩れたら結論を引き直す。** 「音響モジュールも同じ signature なのに表示できている」を根拠に、別機種の危険性を断定しなかった。後に音響側の真因が別（importer の Read/Write 設定）と判明し、この反証は成立しなくなった。**証拠がなぜ証拠なのかを覚えておき、前提が変わったら再導出する。**

### 3. 同じ数字が正反対を意味することがある

「修正前後のレンダー差 0.0 %」が2回出た。

- ノブの目盛りを連続リングに置換したとき → **欠陥の証拠**。置いたリングがベゼルの裏で完全に埋まり、誰にも見えていなかった。
- 表示面の座標フレームを直したとき → **正しさの証拠**。形も位置も見え方も変えずフレームだけを移したのだから、差が出ないのが正解。

**測る前に「うまくいった場合の値」と「失敗した場合の値」を宣言しておく。** 仮説のない数値は情報量ゼロで、都合よく読めてしまう。

### 4. 見えないジオメトリは欠陥。それを見つける検査を持つ

上の埋没リングは、ray が到達しないクラスタを探す検査が `blocked_fraction 1.0`／448三角形として捕まえた。これがなければ「直した」つもりのものを納品していた。

**機能を置き換えたら、置き換え先が想定視点から実際に見えることを確認する。** 存在することと見えることは別。あわせて、三角形バジェットは見える場所にだけ使う。

### 5. 静かに失敗する操作を許さない

- **スクリプト編集の空振り。** 一括置換がアンカー不一致で何もせず、成功したように見えた回が複数あった。以後すべての置換で `count == 1` を表明させた。**前提が崩れたら大声で失敗する**よう書く。
- **コピー＆リネームの残骸。** ツール一式を複製して次工程を作ると、同名関数の二重定義（古い方が新しい方を覆う）、スコープ外の設定、未使用分岐が溜まる。複製後は親との差分を取り、新しいスコープに要らないものを消す。
- **成果物を説明する数値を手で書かない。** 納品文書にチェックサム件数を手書きし、その後にチェックサムを再生成したため、文書と実体が食い違った。2回やった（1回は相手に指摘された）。文書が自分の説明対象の集合に含まれる場合、件数は不動点になる——**安定するまで再生成を回して確認する。**

### 6. 動くものは動かして当てる

可動部は全可動域を 181 姿勢で掃引し、静止部との最小クリアランスを記録した。これで見つかったもの：レバー腕が軸を貫通、トグルのナットが中実で内部干渉、押しボタンのプランジャが中実の缶に埋没、スライダのハンドルがレールのリップと干渉。

**中立姿勢で破綻していないことは、何の証拠でもない。**

### 7. 組み立てられない形を作らない

監査で出た実例：出力ジャックのリングが中実、パッドがジャックの真上、銘板が角のネジの下、ネジが印字の上。

**組立順序をモデル化する。** 実際の手と工具で組めないなら、それは間違った形。ネジ位置・銘板・印字は互いに干渉しうるので、部品配置は「取り付け可能性」を制約として扱う。

### 8. 下流の契約を上流へ引き上げる

Unity側の検証器が禁止しているノード名や表示面の規則を、Blender側の監査にそのまま移植した。欠陥が下流に到達しなくなるうえ、**最も安価な地点で落ちる**。最初の表示面欠陥のあと、mesh-local フレームの検査もここへ追加した。

### 9. PASS / FAIL / REVIEW / N/A を混ぜない

判定は4値で保ち、REVIEW を PASS に丸めず、N/A を PASS に数えず、**REVIEW を消すために部品を削らない**。材料数の共通上限超過は、3工程にわたって REVIEW のまま可視化され、最終的に「この用途では想定内」と正式に受領された。丸めていたら、その議論自体が起きなかった。

## 形に説得力を持たせる

### 1. スタイリングの語彙ではなく、製造の語彙で考える

このテーマの見た目は、**実在する製造工程を名前で列挙する**ところから出てきた。

折り曲げ鋼板のトレイ、取付フランジ、返し縁、ガスケットの見切り、抜き勾配とフィレットを持つ成形ベゼル、実ハードウェア（六角ナット・ワッシャー・セレートリング）で保持された操作部、ボタンヘッド M4 ねじ、角を包むバンパー、押し出しルーバー。

これらはいずれも**製造上の判断**であり、その帰結として形が決まる。「かっこよく見せる」ではなく「こう作られているはずだ」から形を導くと、同じポリゴン数で見え方が変わる。

### 2. 抜き勾配とフィレットが最安のリアリティ

成形品に完全な鋭角もゼロ抜き勾配も存在しない。ベゼルに 0.6 mm の抜き勾配と 2 mm のフィレットを入れるのは三角形数十個の話だが、読み取られ方が変わる。ハイライトの入り方が変わるためで、ディテールを増やすより効率がいい。

### 3. 継ぎ目こそがデザイン

ガスケットの見切り、返し縁、ベゼルが筐体に閉じる際の隙間。こうした線が「複数の部品からできている」という印象を作る。一枚の押し出しの塊は、どれだけ磨いても小道具に見える。

### 4. ハードウェアは句読点

実在の計器は「どう組まれているか」が見えている。妥当な位置のネジは、スケール感とリズムと組立の物語を一度に与える。ただし印字や他部品と衝突させないこと（前章 7）。

### 5. ソフトが決めることを、形に断言させない

ロータリーノブに固定の目盛りを 11 本刻んでいたが、実際の段数はランタイムパラメータであり 11 とは限らない。

**形が嘘をつくくらいなら、何も言わない方がいい。** 連続したリングや、段数を示唆しない向き表示に置き換える。一般化すると、**「その物が何であるか」と「今の設定がどうか」を形の上で分離する**。後者をジオメトリに焼き込むと、設定を変えた瞬間に形が嘘になる。

### 6. ディテールは見えるところへ

埋没リングの件の教訓。三角形予算は視界に沿って配分する——ベゼル前面にはカラーを、裏側には何も置かない。

### 7. プレビュー用マテリアルは飾りではなく診断器具

透明ガラス、暗い文字盤、数値表示にチェッカー、グラフ表示に波形。これで state 間の差が**意見ではなく数値**（平均画素差 3.18 %／2.53 %）になる。

実際これが欠陥を掠んだ：3つの状態ランプが1つのマテリアルを共有しており個別点灯できなかったこと、OFF の画面が明るい発光色を使っていて点灯して見えたこと。

### 8. 中身を遮るものは、もっともらしくても取る

表示パネルのガラスは物理的には正しいが、ランタイム描画の手前に重なっていた。外したところ state 差が 1.0／0.8 % から 3.18／2.53 % へ上がった。**もっともらしさと機能が衝突したら機能を取る。**

### 9. 参照対象は想像せずに実測する

既存の本番 FBX 14 件を読み込んで、ノード名・親子関係・ pivot 座標・ bounds ・三角形数を抽出した。pivot の実値はここから来ている。副産物として2機種が Z-up で作図されていることも判明した（のちのフレーム欠陥の伏線だった）。**既存アセットは仕様書であり、読めば測れる。**

### 10. 予算は機種ごとに切る

当初は一律 7,000／8,000 triangles を提案したが、機種ごとの必要量に基づく個別上限へ変更された。つまみと 1.5 m のパネルに同じ数字を与える理由はない。

### 11. ディテール語彙には代替形を用意する

角のガードを正面に置く設計だったが、4機種では正面が埋まっていて一つも置けなかった。外周の弧に沿って包むバンパーへ変え、緩和した。**主要な置き場が埋まっているときの形を決めておかないと、ディテール言語は破綻する。**

## 製造の語彙 1：板金とプレス成形

計器類の筐体の大半は板金。以下は現場で通る定番の語と、それが**形のどこに現れるか**。寸法はいずれも目安で、材質と板厚で変わる。

### 抜く（せん断）

| 語 | 意味 | 形への帰結 |
| --- | --- | --- |
| ブランキング | 外形を抜く | 外周が一定の表情を持つ |
| ピアシング | 穴を抜く | 穴径は板厚以上が定石 |
| ダレ・せん断面・破断面・バリ | 抜いた穴の断面に出る4層 | **穴の縁は片側だけ丸い**。両面対称にしない |
| クリアランス | パンチとダイの隙間 | 抜き穴はわずかにテーパする |

計器のパネルでは、**抜き穴の入口側に微小な丸み（ダレ）を入れるだけ**で「抜いた穴」に見える。完全なピン角の穴は CG に見える。

### 曲げる

- **曲げ半径**：内側 R は板厚の 1 倍程度が最小の目安。**外側 R = 内側 R + 板厚**なので、曲げの内外で R が違う。これを揃えると即座に安っぽくなる
- **スプリングバック**：曲げた後に少し戻る。実物の直角は完全な 90° ではない
- **ベンドリリーフ**：曲げ線の端に入れる逃がしの切り欠き。これがないと端が裂ける。**トレイの四隅に小さなスリットが入る理由**
- **曲げ線の近くに穴を置かない**：目安で板厚×２＋曲げ R 以上離す。近いと穴が歪む
- **フランジ**：曲げて立てた縁。取付部になる
- **ヘム**：縁を 180° 折り返す。**切り口（バリ）を隠し、剛性を上げ、手を切らない**。前章の「返し縁」はこれ

### 形を出す

- **絞り（ドロー）**：平板を器状に引き伸ばす。深絞りでは側壁が薄くなる（**板厚減少**）。角は必ず R を持ち、ピン角の箱は絞れない
- **ビード**：補強用の細長い凸。平らな面の鳴き止め。**広い面には必ず何か入っている**
- **エンボス**：浅い凸。銘板、位置決め
- **ルーバー**：切って起こした通気口。切り屑が出ず、雨も入りにくい
- **バーリング**：穴の縁を筒状に立ち上げ、さらい板でもねじ山を稼ぐ

### 組む

- **スポット溶接**：打点が一定ピッチで並ぶ。わずかなへこみ
- **リベット / 圧入ナット**：薄板にめねじを付ける定番手段
- **タブ＆スロット**：組むときの位置決め。継ぎ目に小さな矩形穴が見える
- **展開図・曲げ順**：平板に戻せない形・工具が干渉する曲げ順は作れない

> **モデリングへの含意**：板金部品は、**「一枚の板から切り出して折ったもの」として成立しているか**を自問すれば、大半の嘘は洗い出せる。板厚が場所で変わる、外側 R が内側より小さい、曲げでなく溶接でしか作れない角——この辺が「なんとなく CG」の正体。

## 製造の語彙 2：成形・切削・仕上げ

### 射出成形（樹脂）とダイカスト

ベゼル、ノブ、ボタンなど、「型で作る部品」全般。

- **抜き勾配**：型から抜くための傾斜。**1〜3° が定番**。垂直な壁は存在しない。シボ（汗加工）を入れるならさらに深さ分の勾配が要る
- **パーティングライン**：型の合わせ目に残る線。**意図して 1 本入れると実物らしさが一気に上がる**。意図しないと場所を型屋に決められる
- **ゲート跡 / エジェクタピン跡**：樹脂の注入口と突き出しピンの丸い跡。通常は裏側や目立たない面に置く
- **ヒケ**：肉厚の厚いところが冷えて凹む。だから**肉厚を均一にする**のが原則で、補強は塊ではなく**リブ**で行う（リブ厚は肉厚の 50〜60 % が目安）
- **ボス**：ねじ受けの円筒。周囲にリブで支える
- **アンダーカット**：そのままでは型から抜けない形状。スライドコアが要る（＝コスト増）
- **コーナー R**：応力集中を避け、樹脂を流れやすくする。**内隅にピン角はない**

### 切削加工

- **旋削（旋盤）**：回転体はこれ。ノブ、リング、ナット
- **フライス**：**内隅には必ず工具半径の R が残る**。ポケットの四隅がピン角なら、それは切削品ではない
- **面取り（チャンファー）**：C 面。バリ取りと安全のため、**人が触る縁には必ず入る**
- **ローレル**：ノブの滑り止め。直目と綾目（ダイヤモンド）がある
- **公差 / はめあい**：部品同士は必ず隙間を持つ。**隙間ゼロは「一体成形」に見える**

### 仕上げと表示

| 語 | 見え方 |
| --- | --- |
| アルマイト | アルミの薄い発色層。角はシャープなまま |
| 粉体塗装 | 厚い。**角が丸くなり、細部が埋まる** |
| ヘアライン | 一方向の細い筋。異方性のハイライト |
| ビーズブラスト | 均質なつや消し。指紋が目立たない |
| シルク印刷 / レーザーマーキング / 刻印 | 順に「乗っている」「焼いている」「彫っている」 |

> **仕上げを先に決めると形が決まる**。粉体塗装で行くなら 0.3 mm の細線は埋まるので彿っても無駄、アルマイトなら残る。この判断は三角形予算の配分に直結する。

## CAD / CAM の語彙と、そこから来る規律

CAD の語彙が有用なのは、**Blender の操作とほぼ 1 対 1 で対応する**上に、製造可能性の規律がもともと組み込まれているから。

### フィーチャーの語

押し出し、回転（リボルブ）、スイープ、ロフト、**シェル**（中身を抜いて一定肉厚の器にする）、フィレット、面取り、**パターン**（規則的な複製）、ミラー。

この中で形の説得力に最も効くのは **シェル** 。実物の筐体はすべて中空で、**一定の肉厚**を持つ。塊から形を削ると場所ごとに肉厚が変わり、それが「作れなさそうな形」に見える。

### 設計意図（design intent）

CAD の中核概念。寸法を直接書くのではなく、**何が何に依存するか**を書く。「ベゼル内径は窓外径＋クリアランス」のように。

これはスクリプトでモデルを作るときにそのまま使える——寸法をマジックナンバーで散らすと、一つ変えたときに整合が崩れる。実際この工程でも、ベゼル開口径を定数で持っていなかったために、リングを開口の裏側に置いてしまった。

### 基準（datum）

原点と基準面を**先に**決め、すべての寸法をそこから計る。寸法を数珠つなぎで指定すると**公差が積み上がる**（公差スタック）。

これはこの文書の冒頭で書いた**座標フレームの問題と同じもの**。CAD は最初から「どの基準から見た値か」を強制する。3D ツールは強制しないので、自分で規律を入れるしかない。

### 工具アクセス性（CAM 側）

**工具が届かない形は作れない。** 切削ならエンドミルが入る道、型なら抜ける方向、板金なら曲げ工具が干渉しない順序。

これは前章の「組み立てられない形を作らない」を、**工具側から言い直したもの**。ネジを置くならドライバが立つ空間が要る、というだけの話だが、見落としやすい。

### DFM / DFA

製造容易性設計と組立容易性設計。定番の問いはこう。

- 部品数を減らせないか（とはいえ、見た目上の継ぎ目はデザイン資源でもある）
- **一方向から組めるか**：上から順に置いていけるのが理想。裏返しが必要な形はコストが上がる
- **誤組防止（ポカヨケ）**：逆さまに付かない形。非対称な位置決め穴が入っている理由
- 共通部品化：同じノブ、同じねじを使い回す。**シリーズ全体の統一感はここから来る**

## 工業デザイナーの視点

### 面質と連続性

面と面のつながり方には段階がある。

| 連続性 | 内容 | 見え方 |
| --- | --- | --- |
| G0（位置） | 繋がっているだけ | 折れ線が見える |
| G1（接線） | 接線が連続。**通常のフィレット** | ハイライトが連続だが幅が急に変わる |
| G2（曲率） | 曲率も連続 | **ハイライトが滑らかに流れる**。高級感の正体 |

これを徹底したものが**クラス A サーフェス**（自動車外装の基準）。計器類でそこまでは要らないが、**フィレットを一段大きく取るだけで面質は上がる**。

実用的な診断法：**長い帯状の光源を当てて、ハイライトの帯が面をどう渡るか見る**。帯がガクッと折れる、幅が跨ねる、途切れる——そこが面の欠陥。

### シャットライン

部品同士の合わせ目の線。工業デザインでは**品質の見える指標**とされる。

- **幅が均一**であること（広がったり狭まったりしない）
- 線が**形の論理に沿う**こと（面の切り替わり、機能の境界）
- 交差部を濁さない

前章で「継ぎ目こそがデザイン」と書いたものの、正式名と判断基準がこれ。

### 階層（ヒエラルキー）

すべてを同じ声量で語らせない。

- 重要な操作部ほど**大きく、手前に、独立して**置く
- 補助的なものは小さく、まとめて、面に寄せる
- 色数を絞り、**アクセントは操作部と警告にだけ**使う

### 素材のコントラスト

金属・樹脂・ゴムの三種が接すると、それだけで「部品からできている」説得力が出る。光沢、粗さ、色温度を分ける。ゴム（ガスケット、バンパー、ブーツ）は**もっとも安価に実在感が出る要素**。

### アフォーダンスとシグニファイア

ノーマンの語彙。**アフォーダンス**＝形が物理的に許す操作。**シグニファイア**＝それを知らせる手がかり。

ローレットは「回せる」を、くびれは「つまむ」を、ガードリングは「うっかり押すな」を語る。**形が操作方法を説明しているか**を設計の問いにすると、装飾と機能の区別がつく。

### デザイン言語と家族性

同じ R、同じ面取り幅、同じフランジ寸法、同じねじ、同じバンパーを全機種で使い回す。**24 機種を一つの製品群に見せているのはこれ**。寸法の集合を小さく保つことが、そのまま統一感になる。

## 人間工学の視点

数値はいずれも**一般的な目安**で、用途・対象者・手袋の有無で変わる。そのまま使うより、**寸法を根拠を持って決める習慣**のための足がかりとして使うとよい。

### 操作部の寸法

| 操作部 | 目安 | 根拠 |
| --- | --- | --- |
| 指先でつまむノブ | 径 10〜25 mm | 指先のつまみ |
| 手のひらで回すノブ | 径 25〜50 mm | 握り |
| 押しボタン（指） | 径 10 mm 以上 | 指腹の幅 |
| ボタンの移動量 | 3〜6 mm | 押したと分かる量 |
| 隣り合う操作部の中心間距 | 20 mm 以上 | 隣を誤って触らない |
| レバーの握り | 長さ 100 mm 以上 | 手幅 |

**寸法は「何で操作するか」から逆算する。** このスケール感があると、参照物がなくても大きさが伝わる。逆に、ノブが 8 mm や 80 mm だと見る人は理由を言語化できないまま「変」と感じる。

### ステレオタイプ適合

人が**学ばずに期待する対応**。逆らうと誤操作になる。

- 時計回り＝増加・右・開
- 上・右＝ON・増加（地域差あり。電源スイッチは国による）
- 赤＝停止・危険、緑＝運転・正常、黄＝警告
- メータの指針は**正常時に向きが揃う**よう並べると、異常が一目で分かる（計器盤設計の古典的手法）

### 誤操作防止

- **ガード・リング・ざぐり**：重大な操作はうっかり押せない位置へ
- **形状コーディング**：見なくても触れば分かるよう、機能ごとにノブの形を変える（航空機の操縦系では標準）
- **距離で分ける**：紛らわしい操作を隣接させない
- **ロック・二段動作**：引いてから回す、押しながら回す

これらは**すべて形に現れる**ので、モデルの説得力に直結する。保護リングのあるボタンは、それだけで「押してはいけないときがあるボタン」という文脈を背負う。

### 視認性

- 文字高さは**視距離から決める**。目安として視距離の 1/200 程度が下限（ 1 m なら 5 mm 前後）。MR なら想定視距離を先に決める
- **コントラストとグレア**：光沢面は反射で読めなくなる。計器の文字面がつや消しなのはこのため
- **視線と配置**：重要な表示は目線の高さ、操作部はその下

### Fitts の法則

目標が**大きいほど、近いほど速く正確に触れられる**。頻度の高い操作を大きく手前に、まれな操作を小さく奥に。前章の「階層」の定量的な裏付けになる。

## 語彙を Blender の操作へ落とす

語彙は覚えるだけでは意味がない。**具体的なモデリング操作と寸法に紐づいて初めて使える**。

### 対応表

| 製造の語 | Blender での実装 | 具体的な値の目安 |
| --- | --- | --- |
| 板厚 | Solidify、または内外 2 リングを Bridge | 定数で 1 つ持つ。場所ごとに変えない |
| 曲げ R | R 部を 2〜3 セグメントに分割 | 内 R ＝板厚、**外 R ＝内 R ＋板厚** |
| ヘム（返し縁） | 縁を 180° 折り返す小さな断面 | 折り返し長 3〜6 mm |
| ビード | 面上の細長い凸（スイープ） | 幅 6〜12 mm、高さ 1〜2 mm |
| ルーバー | スリット＋起こし板の繰り返し | ピッチを定数化 |
| 抜き勾配 | ロフト上下リングの半径をずらす | 高さ× tan(1〜3°) |
| パーティングライン | 意図的な浅い溝を 1 本 | 幅 0.3〜0.5 mm |
| フィレット | Bevel（セグメント 2 以上） | 1〜2 mm。**1 セグメントは G1 すらない** |
| 面取り | Bevel（1 セグメント） | C0.5〜C1 |
| 内隅の工具 R | ポケット四隅に必ず R | 半径 2〜3 mm |
| ローレット | 放射状の細円柱またはセレーション | ピッチ 1〜2 mm |
| 公差・はめあい | 部品間に隙間を残す | **0.2〜0.5 mm**。ゼロにしない |
| スポット溶接 | 等間隔の浅い円形凹 | ピッチ 25〜40 mm |
| リブ | 背面の薄い板 | 肉厚の 50〜60 % |

### 実装上の注意

**1. 公差をゼロにしない。** 部品間の隙間を 0 にすると、見た目が一体成形になるだけでなく、**同一平面の重なりで z-fighting を起こす**。製造的にも描画的にも同じ答えになるのが面白いところで、この工程では背中合わせの同一平面を `contact_seam` として検出していた。

**2. フィレットは 1 セグメントにしない。** 1 セグメントのベベルは単なる面取りで、ハイライトが連続しない。**大きな面を一つ増やすより、縁のセグメントを 1 本増やす方が見た目の見返りが大きい**。

**3. 寸法は定数と依存関係で持つ。** マジックナンバーを散らすと CAD でいう設計意図が失われ、一つ変えたときに整合が崩れる。この工程で実際に踏んだ——ベゼル開口径を定数化していなかったため、装飾リングを開口の裏側に置いてしまった。

**4. ヘルパを製造工程名で作る。** `bevel` や `ring` のような幾何名ではなく、`gasket_reveal`、`louvres`、`molded_bezel`、`button_head`、`serrated` のように**工程や部品の名前**で持つ。名前が語彙を強制し、同じ語彙が全機種に行き渡る——これが家族性の実装。

**5. 内隅にピン角を残さない。** 切削にも成形にも存在しない。ポケット、溝、リブの付け根——すべて R を入れる。

**6. ブーリアンや Hull の近道を避ける。** この工程では、ハルの n 角形キャップが三角分割でゼロ面積三角形を生んだ。**チューブ（四角面の環）として明示的に作る**と消える。実物も中空なのだから、そちらの方が正しい。

**7. 面質は帯状光源で見る。** テストレンダーに細長いエリアライトを一つ置き、ハイライトの帯が面をどう渡るかを見る。マテリアルを径った白で描くと、色にごまかされず形だけを見られる。

### 順番

語彙を使う順序も決まっている。

1. **用途と操作**を決める（人間工学）→ 主要寸法が出る
2. **工法**を決める（板金か成形か切削か）→ 使える形が決まる
3. **仕上げ**を決める → ディテールの下限が決まる
4. **基準と定数**を置く（CAD）→ 寸法の依存関係が決まる
5. ここまでで初めて**形を作る**
6. **面質とシャットライン**を整える（工業デザイン）

逆からやると、形が先に決まってしまい、あとから製造の理屈を後付けすることになる。**それが「なんとなく崩れている」形の主な発生源**。

## プロの見方：形を三層で読む

プロは細部から作らない。**一次形状 → 二次形状 → 三次形状**の順に決め、上の層が破綻していたら下の層に手を付けない。

| 層 | 中身 | 判定する距離 | 予算の目安 |
| --- | --- | --- | --- |
| 一次（primary） | 外形、プロポーション、塊の数 | サムネイル（64 px） | 三角形の 40〜50 % |
| 二次（secondary） | 分割面、ベゼル、ガード、グリップ断面 | 腕の長さ（MR の標準視距離） | 30〜40 % |
| 三次（tertiary） | ねじ、刻印、ローレット、シボ | 手に取る距離 | 10〜20 %、残りはテクスチャ |

### シルエットが最初の審査

黒で塗りつぶして判別できなければ、二次・三次をいくら足しても判別できない。**四方向の黒シルエットで機種が言い当てられるか**を最初の関門にする。操縦桿なら「角ゲートから斜めに立つ非対称グリップ」がシルエットで読めれば合格。

### 密度にはリズムを付ける

- **休ませる面を作る。** ディテールを全面に散らすと、どこも見られなくなる。目安は「密：中：疎 ＝ 1：3：6」程度
- **ディテールは集めて置く。** 機能の境界（操作部の根元、取付部、分割線の交点）に寄せると、理由のある密度に見える
- **等間隔と等寸法を避ける。** 隣り合う寸法比は 1：1.6〜1：3 を目安に。1：1 は退屈、1：5 以上は別物に見える

### 偶然の一致（タンジェント）を消す

二つの輪郭がちょうど接する、ねじの縁が面取りの縁に乗る、ラインが角をかすめる——こうした**偶然の接線**は、意図のない形として目に引っかかる。重ねるなら明確に重ね、離すなら明確に離す（目安として部品寸法の 10 % 以上）。

### スケールの手がかりを必ず一つ置く

MR では比較物がないため、大きさは形の中の既知寸法で伝わる。M3〜M4 のねじ頭、指の幅のグリップ、1 mm のシャットライン。**実寸の小部品が一つあれば、全体の大きさが読める。**

## ハードサーフェス手法を使い分ける

手法は一つに決め打ちしない。**最終の三角形予算と視距離から逆算して選ぶ**。このプロジェクトは 1 オブジェクト 5,000 tris、1K 共有 atlas なので、ミッドポリが主、必要な箇所だけベイクが基本になる。

| 手法 | 向く場面 | 三角形 | 落とし穴 |
| --- | --- | --- | --- |
| SubD（サポートループ） | ハイポリ原型、滑らかな成形品 | 多い（ベイク元向け） | ループが他の面へ流れて波打つ。穴の周りは「四角の中の円」で受ける |
| ミッドポリ（Bevel＋Weighted Normal） | リアルタイム実機の最終形 | 中 | 大きな平面と小さな面取りが隣接するときだけ効く。曲面同士は効きが弱い |
| ロー＋法線ベイク | 微細な凹凸、刻印、ローレット | 少 | シルエットに出る形はベイクできない。水平に近い面の視差に弱い |
| フローター（浮かせ部品） | ベイク元でねじやパネルを面に載せる | 0（ベイク後） | 縁に浮きの影が出る。面の曲率が大きい場所では使えない |
| デカール（法線付きテクスチャ貼り） | 警告表示、パネル目地、通気孔 | 少 | 透過は Quest で高価。少数に限る |
| ブーリアン | 原型の検討だけ | 不定 | n-gon と細長三角形を残す。最終形は明示的なシェルで作り直す |

### プロが手元に持っている小技

- **面取り幅は 3 段階だけ。** 大（手が触れる縁）・中（部品の縁）・小（装飾的な尾角）。幅がバラバラだと手作業に見える
- **ベベルは「視距離で 1〜2 px のハイライト」が出る幅に。** それより細いとエイリアスになり、太いと粘土に見える
- **ベベルのプロファイルを変える。** 0.5（円弧）だけでなく、0.7〜0.9 で面に張りを持たせると、加工品らしいキレが出る
- **対称で作り、最後に一箇所だけ崩す。** 銘板、ケーブル取出し、アクセスカバーなど機能的な非対称が、形を「製品」にする
- **キットバッシュ（部品集）を育てる。** ねじ、カラー、グランド、ラッチを関数として持ち、寸法を引数にする。家族性は部品集から生まれる

## シェーディングと法線

ローポリの品質の半分は頂点法線で決まる。**形が正しくても、法線が崩れていれば「凹んだ面」「波打つ平面」に見える。**

### 面の大きさで法線を決める

- **Weighted Normal（面積加重）。** 大きな平面の法線を優先し、小さな面取り面に曲がりを押し付ける。ミッドポリで最も効く一手
- **法線転写（Data Transfer）。** 滑らかな代理形状（円筒や球）から法線だけを写し取る。グリップにローレットを掛けても、大きな陰影は滑らかなままになる
- **シャープは角度で一括、例外を手で。** 目安 30〜40°。ただし **シャープエッジは必ず UV の切れ目にする**。切れていないと法線マップに黒い筋が出る
- **接線空間を揃える。** Blender と Unity はどちらも MikkTSpace。エクスポート時に接線を出し直す設定を混ぜると、ベイクした法線が傾く

### 円筒の分割数は画面寸法で決める

多角形の角が輪郭で見えるかどうかが基準。輪郭上の角の凸が 1 px 未満なら十分。

| 標準視距離での直径 | 分割数の目安 |
| --- | --- |
| 20 px 未満（小ねじ） | 6〜8 |
| 20〜80 px（ノブ、カラー） | 12〜16 |
| 80〜200 px（ベゼル、グリップ） | 24〜32 |
| 200 px 以上（大型計器） | 48〜64 |

**分割数は 4 の倍数にする。** 上下左右に頂点が乗り、四角や他の円とブリッジできる。見えない裏側は分割を間引いてもよい。

### よく見る症状と原因

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 平面に陰影のグラデーション | 細長い三角形とスムース法線の組み合わせ | シャープで区切るか Weighted Normal |
| 円筒の端面が凹んで見える | 端面と側面が法線を共有 | 端面の境界をシャープに |
| 面取りに黒い筋 | シャープなのに UV が連続 | そこで UV を切る |
| 結合後に法線が崩れる | 非一様スケール下での join | スケールを適用してから join、または位置照合で復元 |
| ベイクに波状の歪み | ケージが面に密着しすぎる、または接線の不一致 | ケージ距離を広げ、MikkTSpace を揃える |

## リアルタイム予算の配り方

予算は「何枚使ったか」ではなく「**どこに使ったか**」で評価する。同じ 5,000 tris でも、シルエットと手が触れる部分に密集していれば精密に見え、均等に散らすと粗く見える。

### 三角形を買う順番

1. **シルエットの曲線**（輪郭に出る円筒、グリップの外形）
2. **大きなハイライトを受ける面取り**（ベゼルの縁、分割面の段差）
3. **可動部のクリアランスと注視点**（操作部の根元、軸受）
4. 残りを三次形状へ。平面の内側と裏側には買わない

### 実機が数えるのは頂点

GPU が処理するのは三角形ではなく**分割後の頂点**。頂点は次の境界で複製される。

- シャープエッジ（法線の切れ目）
- UV シーム
- マテリアルの境界（サブメッシュ）

だから**シャープと UV シームを同じ線に揃えると、分割が一回で済む**。前節の「シャープは UV の切れ目に」は、見た目と性能の両方から来る規則。レポートには三角形数と並べて Unity 側の頂点数も載せる。

### テクスチャ側の予算

- **テクセル密度を機種間で揃える。** 例：1K atlas で 1 m あたり 512〜1,024 px。一つだけ粗いと、隣に並んだ瞬間に安っぽく見える
- **トリムシート。** 面取り、ローレット、シャットライン、ギザなどを横長の帯として一枚に並べ、UV を帯に合わせて共有する。共有 atlas との相性がよい
- **ミラーと重ね UV。** 対称部品の片側を重ねて解像度を倍にする。ただし刻印や文字が逆向きになる面は除外
- **パディングは最小 mip でも滲まない幅。** 1K なら 4〜8 px が目安

### Quest で高いもの、安いもの

| 高い | 安い |
| --- | --- |
| 透過と重なり（オーバードロー） | 不透明の三角形数千 |
| マテリアル数と renderer 数（ドローコール） | 頂点カラーによるマスク |
| リアルタイムライトと影 | ベイクした AO を atlas に焦き込む |
| 高解像度の個別テクスチャ | 共有 atlas とトリムシート |

ガラスを外したときに表示の差が増えた件（前章 8）は、性能面でも正解だった。

## 可動部の設計技法

2 軸の操縦桿を作ったとき、検査が捕まえた欠陥は 6 件あり、**すべて可動部と固定部の境界で起きた**。可動部は形ではなく、**動きが通過する空間**を先に設計する。

### 回転に対して不変な形を使う

球は中心周りにどう回しても同じ形なので、球面に一定の隙間で沿わせた座とは絶対に干渉しない。軸周りの円筒も同じ。**回転中心を球や円筒の中心に置くと、クリアランス計算が不要になる。** ボールジョイント、ブッシュ、ハブが実物でこの形をしている理由でもある。

### 不変な形からはみ出す部分は円錐で逃がす

操縦桿では、球の外に出ているブーツの首が、球面に沿ったベゼルに食い込んだ。解決は、**回転中心を頂点とする円錐**で開口を広げること。半頂角は次の式で決まる。

```latex
\psi = \theta_{\mathrm{max}} + \arctan\frac{r_{\mathrm{neck}}}{\delta_{\mathrm{neck}}} + \mathrm{margin}
```

θmax は 2 軸を同時に倒したときの合成角（各軸 22° なら約 31°）。単軸の最大角で計算すると対角で当たる。

### ストップは実際に当たる角から寸法を出す

- **当たるのは面取りの外角。** 面取りのない理想の角で計算すると、ストップ角が 1° ずれた。候補の角すべてで計算し、最大値を採る
- **対角は別の部位が当たる。** 斜めに倒すと部品が深く沈み、直円筒のカラーは上部が先にゲートへ当たった。カラーを上すぼまりにすると、どの方向でも下角が先に当たる
- **角ゲートのコーナー R には上限がある。** 対角の可動域を削らない条件は「コーナー R ≤ ゲート半幅 − 部品中心の最大変位」
- **動作域とストップの間に余裕を取る。** ランタイム ±20° に対しストップ 22°。余裕がゼロだと、最大操作で常に擦っている形になる

### 可動部に出っ張りを持たせない

止めねじ、キー、ピンなどは実物でも面一か沈めてある。出っ張った止めねじは、設計したストップより 2° 早くゲートに当たった。**可動部の外周は、意図した接触面以外すべて回転体の内側に収める。**

### 多軸は入れ子の支点で表す

ジンバルは外輪と内輪の 2 段の Empty にし、各 Empty は 1 軸だけ回す。合成の順序が階層で明示され、ランタイム側が Euler の順序を推測しなくて済む。renderer 数は増えない。

### 検査は格子の掃引とストップ角の探索で行う

- 可動域全体を格子で掃引し、**四隅を必ず含める**（±20° × ±20°、2.5° 刻みで 289 姿勢）
- 最小クリアランスは頂点距離で近似し、判定は三角形の重なりで行う
- ストップ角は動作域の外へ 0.25° ずつ進めて初接触を探す。**当たらなければ、そのゲートはストップではない**

## もう一つの操縦桿で検査が捕まえたもの

別のテーマで、コンソール据付のサイドスティックを 1 点作ったときの記録。前章の 2 軸ジョイスティックとは独立した作業で、捕まえた欠陥の系統が違うので並べておく。**6 件すべて目視では気づかず、検査が出した**。

### 生成スクリプトの継ぎ目は、黙っていては溶接されない

回転体を作るヘルパは、断面の点ごとに新しい頂点の輪を作る。そこで**断面を閉じようとして最初の点を末尾に繰り返しても、同じ位置に別の頂点が生まれるだけ**で、面はその線で開いたままになる。見た目は完全な閉じたリングなので、レンダーでは分からない。

この作例では 4 箇所で起きた。固定は、輪を一度だけ作って**最後の帯を輪 0 へ巻き戻す**専用ヘルパを用意すること。

一般化すると：**頂点を都度生成する仕組みは、同じ座標を 2 回書いたところが必ず縫い目になる。** 閉じるつもりの形を作ったら、non-manifold エッジ数を数えて確かめる。

### 平らな部品には平らな地面が要る

銘板をデッキに置いたところ、**補強ビードの上に乗っていた**。実物なら貫かない。

平面を要求する部品（銘板、ラベル、ガスケット、平座、基板）を置くときは、**その下に何があるかを先に見る**。ビード、リブ、ルーバー、溜まり、曲げ R はすべて「地面ではない」。今回はビードを 1 本減らして銘板の場所にした。どちらかを諦めるのが正解で、重ねるのは不正解。

### 固定具と装飾は、同じ問いで一度に見る

同じ回に 2 件出た。**ネジ 4 本が角バンパーの下**（ドライバが入らない）、**スポット溶接痕がトレイの下に埋没**（誰にも見えない）。

どちらも「部品を置いたあと、その上に別の部品を置いた」だけの話で、**平面図では重なっているのが見えない**。部品を追加したら毎回この 2 つを問うと良い。

1. この部品に**工具が届くか**
2. この部品は**想定視点から見えるか**

### 座るものは座面へ沈める

リング、銘板、レンズベゼル、ビードの 4 点が、デッキ表面と**ちょうど同じ高さ**になっていた。製造的にも描画的にも同じ答えになる：**0.4〜0.6 mm 座面へ沈める**。

「ちょうど上に置く」はスクリプトで作ると自然に起きる——`z = DECK_TOP` と書けばそうなる。**部品の座面は定数ではなく、定数から引いた値で書く**のが習慣として安全。

### クリアランスは計算ではなく実測で決める

これが一番役に立つ。ブーツ口とグリップ首の隙間を**手計算で 2 回決め、2 回とも外した**。

- 1 回目: 181 姿勢中 170 姿勢で交差
- 2 回目: 7 姿勢で交差、不足 1.14 mm
- 3 回目（実測で決めた）: 交差 0、最小 2.09 mm

外した原因は、多角形近似（24 角形の辺中点は半径の 0.991 倍）や、側面のテーパを線形で近似した誤差の積み上がり。**値は合っているのに結論が外れる**のでたちが悪い。

手順としては、**寸法を仮置きして掃引を回し、報告された最小クリアランスから逐近する**方が、先に式を立てるより早く確実。前章の「回転に対して不変な形を使う」が使える場面ならそちらが上で、**不変な形にできないときだけ掃引に落とす**。

### この作例の結果

この作例は 5,612 triangles / renderer 4 / material role 3 で、Tier A は FAIL 0。しかしそこに至るまでに上の 6 件と可動干渉 2 回を潰している。**初回のビルドが通ったことは、何の意味もない。**

## 製造の語彙 3：鋳造・押出・溶接・複合成形

板金と成形だけでは、どの機種も同じ顔になる。**工法を一つ増やすと、形の引き出しが丸ごと一つ増える。**

### 鋳造（砂型・ダイカスト）

- **鋳肌と加工面の対比。** 鋳物は全体がザラっとした鋳肌で、取付面・軸受座・シール面だけが平滑に削られる。少し盛り上がった「加工座（パッド）」は、プロがよく使う強いディテール
- **大きなフィレットと厚い肉。** 湯が流れるように角は丸く、肉厚は成形品より厚い（3〜8 mm）
- **分割線のバリ跡。** 外周を一周する細い帯。成形品のパーティングラインより荒く、幅が揺れる
- **鋳抜き穴と鋳出し文字。** 裏側に軽量化のポケットとリブ。文字は印刷ではなく凸で出る

### 押出し（アルミ押出材）

- **一方向に同じ断面が続く。** 側面には押出し方向の細い筋（ダイスジ）が出る。切断面は別の質感
- **T スロット、放熱フィン、レール。** 長い計器やスライダのベースに向く
- **端面は必ずキャップで閉じる。** 樹脂キャップか削り出しの蓋。断面がそのまま見えるのは試作品だけ

### 溶接

- **隅肉溶接のビード。** 角の内側に沿う小さな三角断面。鱗状の波は法線マップ、ビードの基本断面はジオメトリ
- **断続溶接。** 等間隔に短いビードが並ぶ。薄板の歪みを抑える実際の手法で、リズムも出る
- **溶接はフレームとブラケットの語彙。** 筐体外側の見せ面には普通使わない

### 複合成形（二色成形・インサート）

- **硬い芯に柔らかい材料を被せる。** グリップ、ボタン、バンパー。境界は段差になり、柔らかい側が 0.5〜1 mm 浮く。操縦桿のグリップがこれ
- **境界は機能の線に沿わせる。** 手が触れる範囲だけがエラストマー。境界が適当だと塗り分けに見える
- **インサートナット。** 樹脂のボスに金属のめねじが見える。樹脂筐体を金属のねじで留めるときの根拠になる

> 工法は混ぜてよいが、**一つの部品に一つの工法**。鋳物の中に板金の曲げが現れたら、その部品の説明が破綻している。

## 質感で形を補う

質感は形の上に塗るものではなく、**形の情報を増幅するもの**。形から導けるマスクを使えば、手描きせずに実物らしい要素が入る。

### 形から導くマスク

| マスク | 得方 | 使い道 |
| --- | --- | --- |
| 凸の曲率 | 曲率ベイク、または面取り面の選択 | 角の摩耗、塗装の剥げ、ハイライトの強調 |
| 凹の曲率と AO | AO ベイク | 隙間の汚れ、内隅の暗さ、部品の接地感 |
| 上向きの面 | 法線の Z 成分 | 埃の堆積、日焼け |
| 手が触れる範囲 | 操作部からの距離 | シボの磨耗、光沢の上昇 |

### 摩耗の置き方

- **凸にだけ、理由がある場所にだけ。** 全ての角を均等に剥がすのは「CGの摩耗」の典型
- **手と工具が当たる場所。** ねじ頭の工具跡、ノブのローレットの光沢、レバーの握りの光り
- **このプロジェクトは「新品の量産品」が基準。** 摩耗はごく弱くし、汚れは入れない。強い摩耗は物語を語り、計器の読み取りを邪魔する

### 色より粗さが効く

- **素材の差は粗さで出す。** 色が近くても、アルマイト（中粗さ・金属）、成形樹脂（中粗さ・非金属）、ゴム（高粗さ）はハイライトの幅で分かれる
- **粗さに微弱なムラを入れる。** ±0.05 程度の低周波ノイズで、ハイライトが死んだ平面に見えなくなる
- **ベースカラーは明度を極端にしない。** 黒は 0.04 以上、白は 0.8 以下（sRGB ではなくリニア値）。外れると光源に対して不自然に見える

### 形と質感の境界は一致させる

材質が変わる場所には必ず形の境界（段差、溝、分割面）を置く。段差なしに色だけが切り替わると、塗り分けに見える。これはスタイルガイドの「機械加工面と成形面の切り替えは分割面か段差の上で」と同じ規則。

## レビューの道具箱

自分の作品は見慣れるほど欠陥が見えなくなる。プロは**見方を強制的に変える道具**を持っている。各道具は捕まえる欠陥が違う。

| 道具 | やり方 | 捕まえるもの |
| --- | --- | --- |
| 黒シルエット | 発光なしの単色で塗りつぶす | 一次形状の弱さ、判別性 |
| サムネイル | 64〜128 px に縮小 | 密度のムラ、視線の集まる場所 |
| 左右反転 | 画像を水平反転 | 傾き、比率の狂い（目が慣れを失う） |
| グレースケール | 彩度を落とす | 明度の構造、素材の分離 |
| matcap / 白粘土 | 材質を外して単一の材質で見る | 面質、法線の崩れ |
| 帯状光源 | 細長いエリアライトを動かす | G1/G2 の不連続、面取り幅の不揃い |
| ワイヤーフレーム重ね | 形とトポロジーを同時に見る | 見えない場所の密度、細長三角形 |
| 固定カメラ A/B | 同じカメラと光で前後を並べる、または差分 | 変更の効果と副作用 |
| 実物写真と並べる | 同じ画角の参考写真を横に置く | 「CGっぽさ」の正体 |
| 実機 | Quest で視距離と角度を変えて見る | スケール感、エイリアス、表示が出るか |

### レビューの進め方

- **一回の反復で変えるのは一つ。** 複数同時に変えると、どれが効いたか分からない
- **指摘を形の言葉で書く。** 「安っぽい」ではなく「ベゼルの面取りが 1 セグメントでハイライトが途切れる」。定数一行の修正に落とせる粒度まで具体化する
- **距離を変えて 3 回見る。** サムネイル（一次）、標準視距離（二次）、接写（三次）。上の距離で出た問題から直す
- **時間を置く。** 一晩置くのが無理なら、反転とサムネイルで代用する

## ディテールの引き出し帳

ディテールは「何を語るか」で選ぶ。語る内容が機種と矛盾するなら、どれだけ見栄えがよくても置かない。操縦桿にトリガーを付けなかったのは、ランタイムにその入力がないから。

| モチーフ | 語ること | 置き場所 | 使わない場面 |
| --- | --- | --- | --- |
| 加工座（鋳物上の平滑面） | ここが基準面・取付面 | 軸受、取付足 | 成形品 |
| 座ぐり＋キャップボルト | 荷重を受ける結合 | 角、リブ交点 | 印字や銘板の上 |
| ガスケットの見切り | 密閉された筐体 | 分割面 | 開放型のフレーム |
| ケーブルグランド | 電気が来ている | 裏面、底面 | 正面（視線を奪う） |
| ルーバー・スリット | 発熱する中身がある | 側面、上面 | 発熱しない小型の操作部 |
| ゴム足・バンパー | 置かれる、ぶつかる | 角、底面 | 壁設置専用の機種 |
| ガードリング・凹み | 誤操作してはいけない | 重要な操作部 | 頻繁に触る操作部 |
| ローレット・セレーション | 回せる、滑らない | つまみ、リング | 回らない部品 |
| エンドストップ | 可動域に端がある | 可動部の境界 | 無限回転のエンコーダ |
| 銘板パッド | 型式と仕様がある | 平らで見やすい面 | 中身のない表記（意味のない銘板は削除した前例がある） |
| アクセスカバー | 保守できる | 側面、裏面 | 正面の主表示周り |
| ヒンジ・ラッチ | 開く | 蓋の縁 | 開かない筐体 |
| 映り込み防止のフード | 表示を読ませる | 表示面の上 | 操作部 |
| 指かかり・親指置き | こう握る | グリップに 1 箇所 | 2 箇所以上（握り方が曖昧になる） |

### 引き出しを増やす習慣

- **実物を工法で分解して見る。** 身の回りの機器を見たら、部品ごとに「板金・成形・切削・鋳造のどれか」、「どの順で組んだか」を言い当てる
- **分解動画とサービスマニュアル。** 製品の内部構造と組立順序が出てくる。教科書よりも形の理由が分かる
- **モチーフは関数にして残す。** 一度作ったディテールは寸法を引数にした関数にして、次の機種で呼べるようにする。引き出しは記憶ではなくコードで増やす
- **他ジャンルから借りる。** 医療機器の清潔感、航空機の形状コーディング、カメラの質感の使い分け、測定器の階層。同じジャンルだけを見ると形が平均化する

## 持ち出せるチェックリスト

**着手前**

- 参照する既存アセットを読み込んで、ノード名・ pivot ・ bounds ・三角形数を**実測**する
- 消費側が読む値を全部列挙する（どの座標系の、何の寸法か）
- 下流の検証器の規則を読み、自分のパイプラインに移植する
- 製造語彙を先に書き出す（形ではなく工程名で）。主要な置き場が埋まったときの代替形も決めておく

**作図中**

- 変更を測る前に、成功時と失敗時の期待値を宣言する
- 新しい測定手段は、答えの分かっている対象で較正してから使う
- スクリプト編集は全てアンカー件数を表明させる（`count == 1`）
- 部品を追加したら、想定視点から**見えているか**を確かめる
- 名前と意味を一致させる（目盛りでなくなった部品を `ticks` と呼ばない）
- 黒シルエットと 64 px サムネイルで機種が判別できるかを、二次形状に手を付ける前に確かめる
- シャープエッジと UV シームを同じ線に揃える
- 材質が変わる場所には形の境界（段差・溝）を置く

**納品前**

- 可動部を全可動域で掃引し、最小クリアランスを記録
- 組立可能性を見る（中実、重なり、工具が入らない箰所）
- export 後に再インポートして、ノード・三角形数・ bounds を照合（round trip）
- **消費側が読む座標系で**寸法を再測する。作図ツールの視点だけで済ませない
- 判定は 4 値のまま残し、REVIEW を丸めない
- 成果物を説明する数値は、成果物から生成する。手で書かない
- 多軸の可動部は対角（四隅）を含めて掃引し、ストップ角を実測する
- Unity 側の頂点数（分割後）を三角形数と並べて記録する

**パッケージ運用**

- 検証済みのパッケージを**上書きしない**。新リビジョンのディレクトリを切る
- 毎工程後に全姉妹パッケージのチェックサムを再検証し、他を壊していないことを示す
- 相手が検証を終えたあとは、1 バイトも変えない（訂正は文書側に記録する）

## 3D以外にも効く一般則

この工程の教訓の半分は、実は 3D 固有ではない。

**1. 契約は「どの視点から見た値か」まで含めて初めて契約。** API の単位、タイムゾーン、文字エンコード、座標系。「正しい値」は常にどこから見た値かを伴う。片方で検査してもう片方は保証されない。

**2. 検査の信頼性は、不良を落とせると実証したときにのみ生まれる。** 通ることしか確かめていないテストは、何も測っていない可能性がある。

**3. 数値には仮説を先に付ける。** 「差分 0」は成功の証でも失敗の証でもありうる。どちらかを決めるのは数値ではなく、測る前に立てた予想。

**4. 前提が崩れたら結論を再計算する。** 反証として使った事例の原因が別だったと分かった時点で、その反証に依りかかった判断は全部無効になる。

**5. 下流の契約を上流へ。** 欠陥は見つけるのが遅いほど高くつく。審査を最安の地点へ移す。

**6. 出力を説明する数値は出力から生成する。** 人間が転記した瞬間に古びる。自分を含む集合を数える場合は不動点になるので、安定を確かめる。

**7. 失敗と自分の誤りをそのまま報告する。** この工程では件数の転記ミスを2回やっている。1回は相手に指摘され、その場で実測値が正とされた。隠さなければ、誤りは単なる訂正で済む。

——

最後に一つ。この工程で最も高くついた欠陥は、**すべての検査を通過して本番に入った**。見つかったのは実機で「何も表示されない」という報告からであって、自動検査からではない。

だから、**検査が全部通ったことは「正しい」という意味ではなく、「自分が思いついた問いには答えた」という意味しか持たない**。実機で一度見ることに代わるものはない。
